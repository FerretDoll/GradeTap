# GradeTap 第一阶段开发计划与前后端分工

**2026 年 11 月 24 日（阶段化修订版）｜供后端负责人、Claude 前端开发和试点教师共同使用**

第一阶段交付给两位教师试用。每人能用独立账号进入自己的授课班，完成一节 Python 课的备课、作业批改、异常复核及结果导出。管理员能开通、驳回和停用账号，并统一管理共用大模型配置。两位老师可以合教指定班级，学生二次提交后仍能查到首轮证据和教师修订。

**推进方式（按阶段而非固定天数）：** 本计划不设定硬性“每日进度”，而是按严格的前后依赖划分为 **阶段 0–阶段 6**。开发节奏可灵活调整——状态好时一天可推进多个阶段，遇到难点也可多天打磨一个阶段，但**必须满足上一阶段的完成标准（DoD）后再进入下一联调门槛**。前端先用契约样例独立开发页面，后端按批次交付真实接口，每批就绪即切换联调。

## 里程碑门槛

| 里程碑 | 对应阶段 | 目标 | 用什么证明 |
|---|---|---|---|

外部教学与申报节点（如“课堂革命”申报书的学校确认口径与教学周次）仅作阶段目标参照，不倒逼跳过验收门槛。若模型或邮件服务就绪时间有变化，保持下列阶段依赖顺序推进即可。

## 后端实现顺序及原因

1. **账号、模型权限收口与授课关系（阶段 0–2）。** 用户拥有稳定 ID，授课班关联课程、班级、学期和成员；补齐 `GradingTask` 外键，课程名与班级名仅保留为显示快照。同步将 `/api/settings/llm` 收归管理员权限、将查重接口纳入范围校验。先解决身份与对象归属，后续所有接口和智能体查询才能共用同一授权判断。
2. **保护现有批改、查重与历史任务（阶段 2）。** 在现有任务上引入提交轮次、评价版本和证据定位，改写重新准备学生、重新提取证据和重批时的清理逻辑；同时改造 `task_service.py` 的物理删除逻辑：已有教师修订或已发布成绩的任务禁止物理删除、仅允许归档，且任何情况下均不物理删除 `AuditLog`。用自动化 `pytest` 锁定底线：“已改分再重跑或尝试删除，原教师分、评语、原件、审计日志和导出仍可查”。历史归属不清的任务进入待核对清单。
3. **先步骤表跑通双智能体，再接入分布式队列（阶段 3–5）。** 共用模型调用适配、工具注册、运行记录和预算。阶段 3 先用数据库步骤表验证备课检索/审改写入 `CourseAssignment` 与批改按证据选工具/暂停恢复，降低首轮复杂度；阶段 5 再对接 Celery/Redis（及按需引入 LangGraph 检查点）与跨进程 SSE 续读。正式分始终由服务端根据已确认快照产生。
4. **完善管理保障与生产 MySQL 验证（阶段 5–6）。** 审核、停用与模型配置鉴权在阶段 1 即上线；真实发信、协作撤权、旧数据迁移演练、生产 MySQL 迁移、备份恢复与双班并发压测在向真实班级开放前全部验证通过。

| C · 备课与批改智能体 | 阶段 3 | 新增 `POST /offerings/{id}/lesson-drafts`、`PATCH /lesson-drafts/{id}`、`POST /lesson-drafts/{id}/approve`（幂等写入 `CourseAssignment`）；新增 `POST /tasks/{id}/agent-runs`、`GET /agent-runs/{id}`、`POST /agent-runs/{id}/resume`（创建返回 202 与 `run_id`）；实际接通 `reflect-grading` 与 `route-review` | 备课草稿编辑、出处查看、批准转课程作业；批改进度、工具轨迹、补查证据、待办与暂停恢复 |
| D · 教师确认与正式导出 | 阶段 4 | 改造 `PUT /tasks/{id}/grading-results/{result_id}/review`（服务端取当前登录教师 ID）；新增 `POST /tasks/{id}/releases` 固化已确认快照；改造 `POST /tasks/{id}/export-results`（按 `release_id` 导出正式版时完全忽略客户端传入的 `teacher_revisions`） | 教师复核、修订原因、确认发布快照、正式版/草稿版 Excel 导出与待复核计数 |

**统一状态。** 账号生命周期采用 `pending_verification → pending_approval → active`，另有 `rejected` 和 `disabled`。受邀注册验证邮箱后可直接进入 `active`。已验证待审或被驳回的账号可获得受限会话用于查看状态与 `status_reason`（驳回后可补充重提）。账号被停用时服务端撤销旧会话，在线请求返回 `401 session_required`，重新登录返回 `403 account_disabled` 并带提示原因。智能体运行采用 `queued / running / awaiting_review / completed / failed / cancelled`，与成绩发布状态分离。
